# Assessment Lab / «اختبر نفسك» — persistent implementation contract

This file is operational guidance for future maintainers/agents. It is not user-facing content.

## Product goal
Build the strongest responsible Arabic self-check library possible without pretending that local tools are diagnostic tests. Preserve every valid historical route/content item, enrich rather than delete, and never replace evidence with generic filler.

## Fixed portfolio target: 150 public routes
The target is explicitly **150 distinct assessment/self-monitoring routes**. The portfolio must not be filled by cloning templates or renaming the same questionnaire.

Portfolio composition:
- **90 Rawafid-original tools**: original constructs, monitoring sheets, decision-support and reflective tools authored by Rawafid.
- **30 composite pathways**: multi-domain assessment pathways that combine independently authored Rawafid modules around a coherent user question.
- **20 clean-room alternatives**: independently designed Rawafid tools in domains where well-known proprietary/restricted measures exist.
- **10 source/rights routes**: authoritative pages for notable external instruments, with source, population, Arabic-version status, reuse rights and scoring status.

Total: 90 + 30 + 20 + 10 = **150**.

## Absolute scientific completeness rule
A working page with questions is NOT a complete assessment.

No Rawafid-original or clean-room tool may be described internally or publicly as scientifically complete until it has all of the following documented:
1. construct definition;
2. intended population;
3. intended use and explicit non-use cases;
4. reference/recall period;
5. domain/axis map;
6. item rationale and coverage map;
7. response scale whose semantics match the wording of each item;
8. plain-Arabic language review and comprehension review;
9. content-validity review by relevant experts;
10. privacy and data-flow statement;
11. interpretation rules and boundaries;
12. functional-impact guidance;
13. safety escalation rules;
14. professional referral route;
15. scientific references supporting the construct and domain design;
16. version number and change log;
17. declared validation stage.

A generic question template alone can never satisfy this standard.

## Response-scale rule
Do not use one mixed response scale across items that ask different kinds of questions.
- Frequency items must use a frequency scale.
- Degree/intensity/extent items must use a degree scale.
- Direct yes/no experience items must use a yes/no-style response architecture or be rewritten.
- The wording and response options must be semantically compatible in Arabic.

## What “validated” means
`validated` is an empirical status, not an editorial status.

A tool may be labeled validated only after an appropriate empirical program, which may include depending on the construct:
- content validity;
- cognitive interviews/comprehensibility testing;
- pilot data;
- item analysis;
- dimensionality/factor structure;
- internal consistency where applicable;
- test-retest reliability where applicable;
- convergent/discriminant/criterion validity where applicable;
- differential item functioning or measurement invariance where relevant;
- criterion-based cutoff calibration only when justified;
- a public technical manual/version record.

Editorial review, expert opinion, a functioning UI, or a plausible set of questions is never sufficient by itself to claim psychometric validity.

## Development maturity states
Every original/alternative tool must have exactly one maturity state:
- `concept`
- `item-development`
- `expert-review`
- `cognitive-interview`
- `pilot-ready`
- `pilot`
- `psychometric-analysis`
- `validated`

No tool may jump directly from concept/editorial build to validated.

## What “better than a licensed test” is allowed to mean
Rawafid may build an independent tool that is better in **language clarity, accessibility, Arabic/RTL UX, contextual explanation, functional follow-up, privacy, safety escalation, breadth of domains or user usefulness**. Do not claim that it is psychometrically superior, more valid, more reliable, more sensitive or more accurate than an established instrument until a direct empirical comparison supports that claim.

## Clean-room rule for restricted instruments
When a known measure is licensed/restricted:
1. Research the underlying construct from independent scientific literature and clinical/public-health guidance, not from copying the protected questionnaire.
2. Define the Rawafid construct and intended use independently.
3. Generate an original item pool from construct definitions, lived-context examples, functional consequences, protective factors and support needs.
4. Use original Arabic wording and an independently selected response format/reference period.
5. Do not preserve the protected instrument's item sequence, scoring algorithm, thresholds, proprietary subscale names or translation.
6. Document provenance and why the Rawafid tool is independently authored.
7. Until validated, label it as an original monitoring/self-reflection tool rather than a diagnostic or standardized test.

## Composite pathway rule
A composite route is not a hidden sum of unrelated scores. It must:
- answer one coherent user question;
- use modules with explicit constructs and reference periods;
- show each domain separately;
- identify cross-domain patterns without inventing a global clinical score;
- provide next-step guidance and internal links;
- remain transparent about which modules are Rawafid-original and which external source pages are merely referenced.

## Non-negotiable rules
1. Do not delete, hide, orphan or silently replace an existing published assessment route.
2. Every public page must be useful, unique and indexable unless there is a documented legal/safety reason not to index it.
3. Local Rawafid monitoring tools are NOT validated diagnostic instruments unless a completed validation program says otherwise. Do not invent cutoffs, diagnoses, severity bands, norms or psychometric claims.
4. Known instruments must remain clearly attributed to their source. Do not copy protected items, translations or scoring logic unless reuse rights and the exact Arabic version are verified.
5. Answers must not be stored or transmitted unless the product direction is explicitly changed after a privacy review. Current contract: no server submission, no account storage, no localStorage, no sessionStorage.
6. Language must be direct, simple Arabic. Avoid obscure clinical jargon in questions. Each item should be understandable without explanation.
7. Questions must measure/observe a concrete experience, context, functional effect, protective factor or support need. Avoid vague filler and duplicated items.
8. Do not collapse heterogeneous axes into one percentage. Summaries may organize observations but must not masquerade as psychometric scoring.
9. Every tool must include purpose, reference period, privacy statement, interpretation boundary, when to seek professional help, and a route to specialists/guided assessment.
10. Safety escalation must be visible for imminent self/other harm, violence, severe loss of reality testing, acute medical symptoms, or rapid functional deterioration.
11. Public copy should state: «تمت المراجعة من قبل فريق روافد», while clarifying that review does not convert a local monitor into a validated psychological test.
12. Apply Rawafid comprehensive SEO: self-canonical URL, index/follow for reviewed public pages, sitemap inclusion, useful titles/descriptions, structured breadcrumbs, internal links, no keyword stuffing or doorway pages.

## Methodology anchors
At implementation/review time, use up-to-date authoritative methodology, including where applicable:
- COSMIN for content validity and measurement-property methodology;
- FDA guidance for patient-reported outcome instrument development and use context;
- HealthMeasures/PROMIS methodology for modern item-bank, dimensionality and DIF concepts.

These are methodological anchors, not permission to copy proprietary item content.

## Quality gate before merge/deploy
Run the assessment-lab contracts plus repository architecture/build checks. Reject publication if any route is lost, a detail canonical points to the hub, a reviewed route is noindex, answers are persisted/transmitted, fabricated scoring reappears, response semantics are mismatched, scientific-completeness metadata is missing for tools claiming completion, or a restricted instrument is reproduced without verified rights.
