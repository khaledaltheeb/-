## Technical findings

1. The generic `/content/[slug]` renderer still maps technical DB `updated_at` to metadata `modifiedTime` and JSON-LD `dateModified`. This violates the provenance-safe policy when a technical update is not a substantive editorial modification. It is recorded as a systemic blocker; the same template is already under active SEO PR coordination, so this batch does not duplicate/conflict with that code change.
2. The same renderer can use the generic site SEO card as a structured-data `image` when no page-specific image exists. All 50 selected pages lack featured images. The generic social-card fallback is acceptable for social metadata, but should not be asserted as article-specific schema imagery without a real page image.
3. Current main still emits a short public `<meta name="keywords">` subset through the central SEO helper. An existing active SEO PR owns its removal. This batch records rather than duplicates that overlapping fix.
4. The content sitemap currently maps DB `updated_at` to `<lastmod>`. An active SEO PR owns the provenance-safe removal. This batch does not create a second competing implementation.
5. The content sitemap uses canonical namespace ownership, taxonomy exclusions, indexable/published filters, deterministic DB ordering, and de-duplicates rows in the final map. Selected pages fall within the content sitemap namespace.
6. A previous live-preservation gate exposed pagination instability under concurrent publishing. Do not infer real duplicate canonicals from a moving multi-batch read without a stable snapshot/high-water mark. Database checks for this batch found canonical uniqueness intact.
