# Rawafid — Migration Agent Orchestration

## الهدف

تشغيل ستة مسارات متوازية للترحيل (المُنَسِّق + خمسة وكلاء) مع منع التكرار والتعارض والمحافظة على قاعدة «صفحة واحدة لكل عامل في اللحظة نفسها».

## القاعدة العليا

السرعة لا تتقدم على الدقة. كل عامل يملك **صفحة Canonical واحدة فقط مفتوحة في أي لحظة**. لا يبدأ صفحة ثانية حتى يغلق الأولى بالكامل في سجل الترحيل.

كل عامل يجب أن يقرأ قبل أي عمل:

1. `docs/MIGRATION-RUNBOOK.md`
2. `docs/MIGRATION-PROGRESS.md`
3. هذا الملف

ويمنع العمل مباشرة على `main`.

## توزيع المسارات

### Coordinator / Lane C0 — الموسوعة والمصطلحات العامة

- المسؤول: المنسق الرئيسي.
- النطاق: الموسوعة، المصطلحات النفسية/التربوية/العامة، الصفحات التي لا تنتمي بوضوح إلى قطاع واحد، وحل التعارضات بين القطاعات.
- مسؤول إضافي: مراجعة Claims المتداخلة، Canonical decisions، redirects المشتركة، وQA النهائي قبل الدمج.

### Agent 1 / Lane A1 — الصحة النفسية

- الفرع: `migration-agent-1-mental-health`
- النطاق الحصري: الاضطرابات والحالات النفسية، الصحة النفسية العامة، المرأة، الشباب/اليافعون عندما يكون الموضوع نفسيًا أساسًا، العلاج النفسي، الدعم النفسي، الوقاية، الرفاه النفسي.
- لا يعمل على صفحات الإدمان إذا كان الإدمان هو الموضوع الأساسي.

### Agent 2 / Lane A2 — الإدمان والتعافي

- الفرع: `migration-agent-2-addiction-recovery`
- النطاق الحصري: أنواع الإدمان، التعافي، الانسحاب، الانتكاس، الأسرة مع المدمن، برامج الدعم، البروتوكولات والمراكز والموارد الخاصة بالإدمان.
- أي صفحة نفسية يكون الإدمان فيها مجرد عامل ثانوي تُحال إلى A1.

### Agent 3 / Lane A3 — ذوو الاحتياجات الخاصة والدمج

- الفرع: `migration-agent-3-special-needs-inclusion`
- النطاق الحصري: التوحد، الإعاقات النمائية/التعلمية/الحسية/الحركية، الدمج، التيسيرات، الدعم الأسري، التكنولوجيا المساندة، التأهيل، الحياة اليومية، التعليم الدامج.
- يُمنع استخدام مصطلح «معاقين» في المحتوى المنشور؛ تستخدم صياغة «ذوو الاحتياجات الخاصة» أو «الأشخاص ذوو الاحتياجات الخاصة» بحسب السياق.

### Agent 4 / Lane A4 — الطفل والأسرة والمدرسة

- الفرع: `migration-agent-4-child-family-education`
- النطاق الحصري: نمو الطفل، التربية، الأسرة، الوالدية، المدرسة، المعلم، البيئة التعليمية، السلوك الأسري/المدرسي، موارد الأطفال العامة.
- إذا كان الموضوع تشخيصًا نفسيًا بحتًا ينتقل إلى A1، وإذا كان حالة احتياجات خاصة أساسية ينتقل إلى A3.

### Agent 5 / Lane A5 — البحث والأدلة والأدوات والتعلم

- الفرع: `migration-agent-5-research-tools-learning`
- النطاق الحصري: الأبحاث، الأدلة المنهجية، المقارنات البحثية، أدوات التثقيف والتقييم غير التشخيصي، المسارات التعليمية، الدورات، الموارد المهنية، المكتبة الأكاديمية.
- لا ينسخ نتائج الأبحاث القديمة حرفيًا؛ يعيد التحقق من المصادر وتاريخها وسياقها.

## Global Claim Protocol — منع التكرار بين الوكلاء

قبل لمس أي موضوع يجب على العامل:

1. البحث في GitHub Issues عن العنوان، slug، الاسم العربي، الاسم الإنجليزي والمرادفات الرئيسية.
2. البحث في `docs/MIGRATION-PROGRESS.md` عن الموضوع نفسه.
3. التأكد من عدم وجود صفحة Canonical مقابلة في Supabase.
4. إنشاء Claim Issue واحد بالصيغة:

`[MIG-CLAIM][A1][canonical-key] عنوان الصفحة`

يستبدل `A1` برمز العامل الفعلي.

Body الـClaim يجب أن يتضمن:

- Canonical key
- proposed slug
- sector/lane
- Arabic synonyms
- English synonyms
- legacy URLs/files already found
- status: CLAIMED

إذا وجد Claim مفتوحًا لنفس الموضوع أو مرادفًا محتملًا، **يتوقف العامل ولا ينشئ صفحة جديدة**. يرفع التعارض للمنسق C0.

## قاعدة صفحة واحدة لكل عامل

- الحد الأقصى المفتوح للنظام = 6 صفحات في وقت واحد، صفحة واحدة لكل Lane.
- لا Batch داخلي داخل القطاع.
- لا إنشاء 10 مسودات ثم العودة لمراجعتها لاحقًا.
- الصفحة الحالية يجب أن تصل إلى: Discovery → Variants → Dedupe → Rewrite → SEO/E-E-A-T → CMS Draft → QA → Redirect map → Final recorded status.

## ملكية الملفات والفروع

- كل وكيل يكتب فقط على فرعه المخصص.
- لا وكيل يعدل فرع وكيل آخر.
- لا وكيل يدفع إلى `main`.
- الملفات المشتركة (`MIGRATION-RUNBOOK`, `MIGRATION-PROGRESS`, orchestration) تعدل فقط بواسطة المنسق C0 لتجنب Merge conflicts.
- الوكيل يوثق نتيجة صفحته داخل ملف مستقل تحت:
  `migration-records/<lane>/<MIG-ID>-<slug>.md`
- المنسق C0 هو الذي يدمج النتيجة في سجل التقدم المركزي بعد المراجعة.

## قواعد المحتوى الملزمة لجميع الوكلاء

- لا نسخ ولصق من الصفحات القديمة.
- دراسة جميع النسخ والطبقات التاريخية للموضوع قبل الكتابة.
- استبعاد تعليمات الوكلاء، خطط العمل، TODO/QA، المحادثات والملاحظات الخاصة، ونصوص النظام.
- لا حشو للوصول إلى عدد كلمات.
- الهدف المعتاد للصفحة الموسعة 1500+ كلمة عربية مفيدة عندما يسمح الموضوع بذلك.
- H1 واحد فقط، وبنية H2/H3 منطقية.
- التعريف الرسمي من المصدر الرسمي/المرجعي الصحيح متى وجد.
- لا Claim طبي/نفسي غير مدعوم.
- الأسئلة الشائعة تخدم نوايا البحث ولا تكرر الفقرات.
- SEO كامل وفريد لكل صفحة.
- Canonical واحد فقط لكل موضوع.
- Redirects لكل النسخ القديمة التي تمثل الموضوع نفسه.
- الصور تحتاج Alt دقيق.
- المحتوى المهني والتعليمي لا يُحجب بلا سبب؛ التحذيرات تستخدم فقط عند وجود خطر/متطلب قانوني/مهني حقيقي.
- أدوات الأعراض/التقييم توجّه ولا تدعي التشخيص.

## بوابة الجودة قبل اعتبار الصفحة منجزة

لا تُعد الصفحة منجزة حتى يثبت العامل:

- كل النسخ المعروفة فُحصت.
- لا يوجد Claim أو Canonical مكرر.
- النص الداخلي/الخاص استُبعد.
- المصادر الأساسية تحققت.
- H1/H2/H3 صحيحة.
- SEO/E-E-A-T مكتملان حسب نوع الصفحة.
- الروابط الداخلية والـRedirects محددة.
- الصفحة اجتازت Workflow المطلوب.
- تم تسجيل نتيجة QA.

## سياسة التعارض

عند اختلاف قطاعين على ملكية صفحة:

- لا يقرر الوكلاء فيما بينهم بالكتابة المتوازية.
- يتوقف كلا المسارين عن هذه الصفحة فقط.
- C0 يحدد Canonical owner ويحدد علاقات cross-sector عبر additional categories/tags/internal links بدل تكرار الصفحة.

## قياس السرعة

لا يُقاس الأداء بعدد الملفات المنقولة، بل بعدد صفحات Canonical الصحيحة المغلقة دون إعادة عمل أو Duplicate. الزيادة المتوقعة من التوازي تعتمد على حجم التحقق لكل صفحة ولا تُفترض نظريًا أنها 6× دائمًا.
