# Addiction Atlas continuity contract

Target repository: `khaledaltheeb/-`.

## Baseline that must not regress
- 54 substance/family records.
- 34 editorial, indexable comparison pages.
- 8 independent risk dimensions: acute toxicity, overdose, dependence, medical withdrawal risk, neuro harm, cardio harm, respiratory harm, polysubstance risk.
- At least 7 curated epidemiology records and 6 mortality records, each retaining year, geography, metric definition and a resolvable source ID.
- Arabic + English display names on every substance page.
- Arabic transliterations, aliases and misspellings are for search resolution/metadata only; never publish them as hidden keyword stuffing.
- `null` means evidence is insufficient. Never replace it with a guessed score.
- No use-dose instructions, mixing recipes, intoxication optimization, or self-managed dangerous withdrawal schedules.
- Every substance record keeps direct source URLs and evidence grade A/B/C/U.
- Population statistics must never be converted into personal risk probabilities, and category-level numbers must never be assigned to an individual substance without an explicit source-level mapping.
- No existing published page may be deleted, hidden or converted to `noindex` as part of atlas work.

## Source snapshot
The migrated scientific dataset is pinned to historical source repository commit `00014486191027349cc083e824e545da186d74d1`. Runtime code serves the hash-verified vendored snapshot in `data/addiction-atlas/`; it must not fetch the old repository at request time and must never read a moving `main` branch. To update the atlas, deliberately change the pinned commit and the expected blob hashes only after `npm run addiction-atlas:validate` passes and the scientific/content change is reviewed.

The vendored snapshot includes the wave manifest, methodology, comparison intents, substance waves, epidemiology, mortality and the statistics source registry. A vendor refresh must preserve all of these layers together so that no numerical record becomes detached from its source metadata.

## Required publication surfaces
- `/addiction/substances/`
- `/addiction/substances/[slug]/`
- `/addiction/compare/`
- `/addiction/compare/[slug]/`
- `/addiction/prevalence/`
- `/addiction/mortality/`
- `/addiction/methodology/`
- `/sitemaps/addiction-atlas.xml`

The root sitemap index must include the atlas sitemap. The addiction sector navigation must expose the atlas, comparisons, population evidence surfaces and methodology. Comparison and evidence pages must remain printable in an RTL A4 layout without turning a lower score on one axis into a blanket safety claim.
