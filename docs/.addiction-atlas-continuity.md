# Addiction Atlas continuity contract

Target repository: `khaledaltheeb/-`.

## Baseline that must not regress
- 54 substance/family records.
- 34 editorial, indexable comparison pages.
- 8 independent risk dimensions: acute toxicity, overdose, dependence, medical withdrawal risk, neuro harm, cardio harm, respiratory harm, polysubstance risk.
- Arabic + English display names on every substance page.
- Arabic transliterations, aliases and misspellings are for search resolution/metadata only; never publish them as hidden keyword stuffing.
- `null` means evidence is insufficient. Never replace it with a guessed score.
- No use-dose instructions, mixing recipes, intoxication optimization, or self-managed dangerous withdrawal schedules.
- Every record keeps direct source URLs and evidence grade A/B/C/U.
- No existing published page may be deleted, hidden or converted to `noindex` as part of atlas work.

## Local scientific snapshot and provenance
The runtime dataset is committed under `data/addiction-atlas/` in this repository. Runtime code and the atlas contract must read these local files only; production must not depend on GitHub or another repository being reachable.

The initial migrated snapshot retains provenance to historical source commit `00014486191027349cc083e824e545da186d74d1`. The eight vendored JSON files were imported only after exact Git blob SHA verification and JSON parsing. This source commit is provenance, not a runtime dependency.

To update the scientific dataset:
1. Review the proposed scientific/editorial changes and preserve unknown values as `null` rather than guessing.
2. Update or deliberately re-vendor the local `data/addiction-atlas/` snapshot with immutable provenance.
3. Run `npm run addiction-atlas:validate` and the repository quality/Cloudflare validation gates.
4. Verify staging and production atlas routes, indexability and sitemap coverage after deployment.
